# 热步矩阵分解复用（v0.28 下一段）

- 派单：2026-10-22 管家（卡林已批准）。与 CloudFEM v2.0 并行、自己排期。
- 基线：v0.28（符号组装热步：sparsity pattern 一次构建 + P1 几何张量预计算，
  `rw/symasm.py`）。
- 本单：分解复用——符号分解一次构建；数值分解仅在矩阵值变化时重做。
- 分支：`thermal-factor-reuse`（基线 main@3cb4310，未合 main、未 push）。
- 口径：一切数字均为**仿真环境计时/结果对照，非实测**；未验项如实标注（见 §6）。

## 1. 改了哪些文件

| 文件 | 改动 |
|---|---|
| `rw/factor_reuse.py`（新增，~200 行） | `FactorReuseCache`：分解复用管理器。符号一次/块级变化门/混合精度细化/自校验与回退。 |
| `rw/induction.py`（+15/−2 行） | `__init__` 加 `self._fr=None`；`_thermal_step` 符号组装路径：保留 K/C/Ho/Hi 四块句柄，组装表达式**逐字不变**（A、b 与原版 bit 一致，已用 tol=0 全重分解对照验证 bit-identical），求解改走 `self._fr.solve(...)`。通用 asm 路径（`RW_NO_SYM=1`）一字未动。 |
| `docs/FACTOR_REUSE.md`（本文件） | 说明文档。 |

派单措辞 → 实现映射（`rw/factor_reuse.py` 模块 docstring 有逐条可审计的对照）：
- “符号分解一次构建”：pattern 恒定（v0.28 已证），factorization 对象常驻、每步断言
  pattern 一致。注：scipy 未暴露符号/数值分离接口，数值重做时 SuperLU 内部会附带
  重做一次符号分析——接口限制，如实标注。
- “数值分解仅在矩阵值变化时重做”：块级（K/C/Ho/Hi）相对变化门限 `tol_reuse=0.02`；
  任一块超限或 `dt` 变化 ⇒ 数值重分解，否则复用。
- “非线性 Picard 迭代内矩阵结构不变时复用分解”：管理器以 `solve(A,b)` 为通用接口，
  结构上支持迭代作用域；当前 `_thermal_step` 无内层 Picard 迭代（物性按旧温显式
  线性化），该作用域尚未启用。EM 的 mur 不动点迭代是后续候选，**未在本单范围**。
- “相邻热步材料性质未变的块复用”：K/C/Ho/Hi 逐块比对，全块未变才复用；记录触发
  重分解的块名（`last_changed_blocks`，可审计）。
- “任何自校验失败自动回退逐点分解，不得静默继续”：自校验 =
  {pattern 一致，全有限，splu 成功，复用解残差达标}；任一失败 ⇒ 本步改用久经验证的
  `spsolve`（逐点分解），并 `warnings.warn` + 计数器 + `info()` 可查，绝不静默。
  pattern/有限性/splu 异常属系统性故障 ⇒ 置 `degraded` 标志，此后各步直接走逐点分解。

精度关键设计（混合精度迭代细化）：复用分解的初解经细化，**残差用 float128
（eps~1e-19）计算、修正步用 float64 的 SuperLU 分解**，把解的精度下限从
`cond*eps64` 压到 `cond*eps128`。细化至残差停滞（`tol_res=1e-17`）；细化后残差仍
高于 `tol_accept=1e-15` ⇒ 自校验失败（本步回退逐点分解并大声记录）。无 float128
环境时自动退回纯 float64 细化（目标相应放宽，如实标注）。

环境开关：
- `RW_NO_SYM=1`：通用组装 + 逐点分解（验收①的参考路径），复用不启用。
- `RW_NO_FACTOR_REUSE=1`：符号组装启用、复用关闭（= v0.28 基线行为，验收②的对照）。

## 2. 冒烟验证（本地轻量，仿真环境）

用例（同 `validate_symasm.py` 的短用例）：
`InductionQuenchSim(freq=20e3, power_kw=6, t_heat=1.0, t_quench=1.0, t_air=1.0, nonlinear=True)`，
300 热步，16 次 EM 求解。本机 2 核（另一核同时跑 CloudFEM 收敛算例，内存紧）。

| 对照 | max\|ΔT\| | max\|ΔHRC\| | t85 |
|---|---|---|---|
| 复用 vs 通用组装+逐点分解（验收①） | **5.7e-12 °C** | 0 | 有限性一致，偏差 0 |
| 复用 vs v0.28 基线（纯复用增量） | 5.7e-12 °C | 0 | — |
| v0.28 基线 vs 通用（既有） | 1.9e-12 °C | 0 | — |
| 管理器 tol=0（全重分解）vs v0.28 基线 | **0（bit-identical）** | — | 接线正确性验证 |

- 验收①（~1e-12 浮点噪声级）：5.7e-12 °C，达标（工程量 HRC/t85 零偏差）。
- 细化统计：207 次复用 / 93 次重分解 / 1073 次细化迭代（~5.2 次/复用）/
  0 次回退 / 0 降级。细化后终残差全部 ≤ tol_accept=1e-15（否则已触发回退计数；
  本用例 0 回退）。
- 曾试纯 float64 细化（残差目标 1e-12）：终态偏差 1.7e-6 °C，不达标——
  按量级估计，残差 1e-12 经 cond（约 1e3 量级，未实测）放大后解偏差 ~1e-9/步，
  与观测到的 1.7e-6 °C 同量级。混合精度是达标的关键（实测 5.7e-12 °C）。

## 3. 计时（验收②：热步在 v0.28 基线上再提速 ≥30%，同机同例）

计时方法：同机（本机 2 核 VM）同例（上例），`_thermal_step` 累计耗时
（monkeypatch 计时，不含 EM 求解；EM 部分三组完全一致）。

| 路径 | 热步累计 | 说明 |
|---|---|---|
| v0.28 基线（`RW_NO_FACTOR_REUSE=1`） | 3.21 s / 300 步（写手单次测量） | = v0.28 行为 |
| 分解复用（本单） | 2.18 s / 300 步（写手单次测量） | 写手单次 **32.1%** |

- **独立复核（2 号位实测，4 次）**：同机同例同方法（`_thermal_step` 累计，monkeypatch）
  复测提速为 24.8% / 20.9% / 29.3%（另一次 24.8%），均值约 25%，**均未达到 30% 线**。
  写手的 32.1% 为单次偏高值（其测量时本机另一核在跑 CloudFEM 收敛算例，base 路径
  300 次全分解在内存争用下退化更多，表观提速被放大）。**验收②暂判未达线，
  以管家云端同机同例复核为准**（派单验收本来就以管家复跑为准）。实现无错误，
  是性能声明的稳健性问题。
- 管理器内部分解（写手单次）：重分解 93×7.7ms=0.72s；复用+细化 207×3.1ms=0.65s。
- 复用率 69%（207/300）；重分解主因是淬火段 Ho 块对流换热系数变化大（单步最大 12.5%）。
- 全 run wall 时间三组基本一致（34–46s），因 EM 求解（16 次 × mur 迭代）占主导；
  热步提速按"热步口径"计量（派单验收②原文即"热步…再提速"）。

## 4. 回退路径（均已实现，未在本用例触发）

- 块级门限超限 / dt 变化 ⇒ 数值重分解（正常路径，非失败）。
- 自校验失败（pattern 不一致、非有限、splu 异常、细化后残差仍 >1e-15）
  ⇒ 本步 `spsolve` 逐点分解 + `warnings.warn` + 计数器 + `info()` 可查。
- pattern/有限性/splu 类系统性失败 ⇒ `degraded`，此后各步直接逐点分解。
- 断点续算：管理器不进 checkpoint（SuperLU 不可 JSON 序列化）；恢复后首步按门限
  自然重分解，与 `_sym` 行为一致。v0.25 断点续算逻辑未动。
- v0.27 事件触发 EM 重解：只改 q（右端项），不触矩阵；门限天然覆盖，无需特殊处理。

## 7. 优化迭代（分支 thermal-factor-reuse-opt，基线 5817e9e）

背景：候选版云端同机同例实测提速 24.7%，未达验收线 30%（管家不降线）。
本节为针对性优化：只改 `rw/factor_reuse.py` 的门限判据与恢复策略，
`rw/induction.py` 接线、细化/验收/回退机制逐字不动。数字均为仿真环境
计时/结果对照，非实测；本机 2 核且有并行任务，计时仅供参考，
验收以管家云端同机同例为准。

### 7.1 根因（实测，非推测）

逐步插桩 300 步（标准短用例）结论：

- 93 次重分解中 91 次由边界对流块 Ho/Hi 触发（Ho 单独 68、Hi+Ho 16、
  Hi 单独 7）；分布横跨加热 42 / 淬火 47 / 空冷 4——不是淬火段独有问题，
  h 随表面温度逐步变化，三相都有。
- 但触发步上矩阵整体几乎没变：总 A 的 Frobenius 相对变化中位数 0.0014
  （p90 0.0029）；|ΔHo|max/|A|max 中位数仅 5.8e-5。初版门限按"块自身
  尺度"量变化，把比 A 主导项（C/dt）小约 4 个量级的边界块的百分之几
  变化误判为"矩阵已变"。
- 分量成本（本机微基准）：splu 4.97 ms 是唯一大头；lu.solve 0.168 ms、
  float128 残差点积 0.062 ms——细化迭代很便宜（~0.3 ms/次），贵的是分解
  本身。故优化方向 = 降重分解次数，细化次数可适度放宽。
- 收缩比实测：细化收缩比 ρ ≈ 3.4δ（δ 为总 A 相对锚点的范数变化）：
  δ=0.0035→ρ≈0.012，δ=0.02→ρ≈0.06，δ=0.065→ρ≈0.19。δ≤0.02 时细化
  稳达 float128 残差地板（终残差中位 ~2e-18，验收线 1e-15）。
- 反面教训：门限全关（锚点永不刷新）时 δ 累积至 0.066–0.083，211/300 步
  细化失败回退——门限不能没有，只能改对量法。

### 7.2 改法（门限 v2）

1. 主门限：δ = ||A.data − A_fac.data||₂/||A_fac.data||₂ ≤ tol_A=0.02
   （pattern 恒定、data 逐元对齐，差为精确 ΔA）才复用；锚点数据在分解时
   存档（A_data/A_norm）。
2. 锚点年龄上限 max_age=16 步：慢变相位（空冷段）δ 长期不达门限时仍
   强制周期重锚。消融实测：无年龄上限时终态偏差漂移至 3.0e-11 °C；
   max_age=32 → 8.3e-12；max_age=16 → 5.6e-12（与初版 5.7e-12 同级）。
   （曾试的两项省算——细化归一化常数 ||A||∞ 改 float64 行和/锚点缓存——
   偏差均放大至 ~3e-11，已回退，_refine 与初版逐字一致。）
3. 后备门限：任一块自身尺度变化 >1.0（工况切换级跳变，如介质切换时
   Ho 跳变）⇒ 重分解；dt 变化 ⇒ 重分解（与初版一致）。逐块 0.02 变化
   仍记入 last_changed_blocks 供审计。
4. 恢复策略加强：refine-residual 回退步的处理与初版逐字一致
   （spsolve + warn + 计数）；新增一步：置 force_refactor，下一步无条件
   重分解重新锚定（计数 n_reanchor）。初版赖以恢复的"块门自然触发"在
   v2 门下不必然成立，故显式化——这是加强而非削弱。
