# 外部 AI 代码生产：环形交叉评审流程 v1（常设）

适用：Qwen、Gemini、ChatGPT 等外部 AI 为 realworld_sim 写代码。只用通用、公开安全的技术内容。
全部结果是程序运行/仿真结果，不是实测。外部 AI 的产出一律标"外部 AI 生成，经评审"。

## 1. 流程
1. 我方出任务提示词：接口逐字固定，写明规则、非法输入、类型、性能要求，并要求自带测试。
2. 环形三跳：作者 A 写 → 审查者 B 审并修 → 审查者 C 审并修。每次任务轮换第一作者（Q→G→P、G→P→Q、P→Q→G），三个顺序都要覆盖。
3. 每一跳保存：模型原始回复全文；该跳之后的完整代码。
4. 我方独立终检：写独立参考实现和验收测试（解析解/独立数值积分/暴力法对照），先拿自己的参考实现跑一遍确认验收本身没写错，再对每一跳的代码分别跑。
5. 通过终检才合并，合并时补我方回归测试，头部标注来源与评审。
6. 不再做"同一提示词各写一份、只由我方打分"的单人模式；基线对比用环内的 hop1 与 hop3 即可。

## 2. 审查跳固定指令（原样使用）
1. 逐项对照规格检查：接口、返回键、公式、边界与非法输入、类型、不改入参、性能。
2. 能运行就运行自带测试并贴输出结尾；不能运行写"未运行"。
3. 直接修好问题，给修订后的完整文件。
4. 单列改动清单：位置 / 原因 / 严重程度。
5. 如实列没检查的部分。
6. 禁止为过测试改期望值，禁止删功能；发现测试写错要单独说明理由。

## 3. 记分（只记确定数字）
- 每跳通过率（我方验收项数）；
- 每个审查者的净提升或倒退（有无"越审越差"）；
- 改动清单是否属实（声称修好的项是否真的变好）；
- 终点对比各模型此前的单人成绩。
- 交付完整性：文件齐全、测试能运行、有无截断。

## 4. 红线
- 不给外部 AI 私有材料、凭据、雇主资料；
- 外部 AI 自称"已通过/已审"不算数，以我方复跑为准；
- 不付费；额度或收费问题先报。
